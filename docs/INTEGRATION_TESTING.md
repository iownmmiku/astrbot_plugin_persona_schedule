# 验证与故障排查

自动化测试分为行为测试、真实 AstrBot SDK 离线集成、实际聊天平台联调。三者验证范围不同，离线通过并不代表 QQ、Telegram 等平台已经送达。

## 1. 行为回归

在插件仓库根目录执行：

```powershell
python -m unittest discover -s tests -p "test_*.py"
node --test tests/test_ui_state.cjs
```

这些测试使用 AstrBot 接口替身，无需模型密钥或机器人账号。主要验证忙碌静默、合并补回、慢回、白名单、模型选择、任务阶段、锁定安排、队列可靠性、跨日归档、主动日程与画卷联动契约。实际测试文件以仓库 `tests/` 目录为准。

Node 回归通过 VM 执行真实 `app.js`，仅替换页面渲染、DOM 和桥接。覆盖人设切换失败的选择回退与草稿保留、异步响应乱序、加载/保存时禁用编辑、键盘/拖动保护、角色时区今天与历史日期，以及失效任务解锁和网络错误重试。它不代替浏览器布局检查或真实 AstrBot 页面桥接验证。

## 2. 真实 AstrBot SDK 离线集成

仓库提供 `tests/smoke_astrbot.py`，使用已安装的真实 AstrBot `Context`、原生插件 Web API 请求对象、事件对象、SQLite 数据库、人设和对话管理器。模型提供商和平台适配器使用本地记录型实现，所有回复只写入内存及隔离数据库，不会联系现有聊天用户或请求外部模型。

桌面版 Windows 示例：

```powershell
& 'D:\AstrBot\backend\python\python.exe' -B tests/smoke_astrbot.py `
  --astrbot-path 'D:\AstrBot\backend\app' `
  --site-packages 'C:\Users\你的用户名\.astrbot\data\site-packages'
```

源码部署示例：

```sh
/path/to/astrbot/.venv/bin/python -B tests/smoke_astrbot.py --astrbot-path /path/to/astrbot
```

`--astrbot-path` 必须是包含 `astrbot/` 包的目录。脚本在导入 AstrBot 之前，把 `ASTRBOT_ROOT` 指向插件 `.qa/` 下新建的临时目录。不会加载已有 AstrBot 配置、账号、密钥、插件或数据库，也不会启动平台适配器。测试结束后清理此临时目录。建议使用 AstrBot 自己的 Python 与依赖，以避免宿主依赖版本差异。

若验证特定版本，先取得对应官方源码标签并把 `--astrbot-path` 指向该目录；`holidays` 等插件依赖需安装到测试解释器或通过额外 `--site-packages` 指定。

成功时输出 JSON，其中 `mode` 为 `offline-real-sdk`，并明确标记外部模型和外部平台尚未验证。检查包括：

- 官方 `PluginPageService` 实际扫描 `pages/schedule/`、加载页面组件与翻译，返回可打开的入口。
- 实际 HTML/CSS/JS/vendor 服务、模块路径改写、主题和桥接初始上下文；页面令牌签名、60 秒有效期、作用域与目录越界检查。
- 原生 Web API 注册、请求上下文、JSON 返回及默认关闭状态。
- 从 AstrBot 读取已加载的聊天模型，返回内容不包含提供商密钥。
- 使用真正的人设和对话管理器创建隔离数据，并分别选择日程与补回模型。
- 真正的消息事件在忙碌时停止处理；两条留言在恢复联系后合并为一次本地发送。
- 补回写入 AstrBot 对话历史，再次检查不会重复发送。
- 日记在结束日期自动归档一次，独立日记模型、只读历史 API 和重写修订号。
- 主动联系上下文遵守忙碌状态，提供当前活动且不发送消息。
- 忙碌时经真实 WakingCheckStage 和 StarRequestSubStage 执行内置 reset，SQLite 对话更新且命令不进入队列。
- 连续聊天触发有限睡眠延后，日程模型独立判断、真实 ProviderRequest 带倦意，基础日程保留。
- 诊断读取不会触发生成或额外发送。
- 原生预演 API 只读检查策略，不修改日程、队列或对话状态。
- 保存编辑、列出快照和恢复快照，恢复前状态也可找回。
- 重复规则 API 保留虚构历法映射，并精确展开跨年活动。
- 真实消息事件和 LLMResponse 进入白名单日记素材，归档只保留数量摘要，移出名单清理未归档原文。
- 使用官方人设管理器在保存/恢复等待锁期间修改人设，旧请求被拒绝，内存与磁盘保持不变。
- 首次空对话经真实 ProviderRequest 绑定至新建 SQLite 对话，用户和机器人回复归为同一个日记会话；执行内置 reset 后排除迟到回复。
- 过期编辑通过原生请求返回 HTTP 409，日程保存携带读取版本。
- 突发抽签、模型生成、忙碌静默、结束后合并一次补回、画卷上下文及只读模拟共享实际日程。
- 独立备份校验、分享导出去除私密字段、预览后仅恢复选定角色，队列和抽签记录不被回退。
- 日记归档缓冲、来源更新提示，以及模型用途统计和后台调用上限的只读查询。

## 3. 实际聊天平台联调

使用自己控制的测试会话进行。插件不会为联调自动向已有用户发测试消息。

1. 在 AstrBot 安装插件，打开「生活日程」视图，在「诊断」查看 Web API、后台任务和当前人设是否正常。
2. 在设置中刷新模型列表，分别选择「日程生成模型」与「留言补回模型」并保存。两者可相同，也可使用不同的 AstrBot 聊天模型。保持 AstrBot 正常聊天模型设置不变。
3. 使用测试会话发送 `/日程会话`，开启白名单并只加入这个来源 ID，再启用插件。
4. 在当前人设的今天安排中，将现在的一段设为「忙碌」，几分钟后的下一段设为「空闲」。整天必须覆盖 `00:00–24:00`，保存后发两条测试留言。
5. 忙碌期间应完全静默。留言页应显示两条待回，诊断页应显示相同人设和对话。
6. 到达空闲段后，等待一个后台检查周期。应只收到一条短回复，同时参考两条留言；待回数量清零，诊断显示最近一次发送结果。再等待两个检查周期，确认没有重复发送。
7. 把现在的安排改为「半忙」，设置这一段专用的慢回范围。发送两条消息，应在范围内合并补回，后来的消息不会不断推迟首次等待时间。
8. 切换 AstrBot 对话或人设，确认旧队列暂停，不把旧角色的留言发到新对话。将测试来源移出白名单，确认正常聊天恢复。
9. 关闭插件，恢复测试日程与设置。不要为了验证失败分支撤销现有平台账号或破坏网络配置。

## 诊断中的发送结果

“成功”表示 AstrBot 找到了平台，且平台发送方法正常返回；并不等价于用户已读。平台返回失败时保留队列并退避重试；发送抛出异常或重启时结果不确定，则停止自动重发，避免重复消息。先核对聊天记录，再手动重试或清除。

模型错误只显示错误类型和检查建议，不展示可能含密钥的提供商原始异常。查看 AstrBot 本地日志时，也应避免把含账号、会话来源 ID 或服务凭据的完整日志公开上传。
