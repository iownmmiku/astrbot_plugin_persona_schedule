# 2026-10-29 检查记录

本次以 v0.3.3 为基线检查数据保留、消息拦截、临时提示与页面状态，修复发布于 v0.3.4。未扩大对话控制范围或增加默认开启的聊天功能。

## 已修复的问题

| 场景 | 原问题 | 修复 |
| --- | --- | --- |
| 切换角色或日期时加载失败 | 新选择器仍显示旧详情，可能把 A 的草稿保存给 B | 详情绑定人设与日期，失败回退；加载和保存期间禁用编辑，过期响应不覆盖新选择 |
| 任务记录已被清理或插件重载 | 任务查询无限重试，页面一直锁定 | 识别失效任务并解除锁定；普通网络故障继续重试 |
| 浏览器与角色在不同日期 | 首次打开停留在浏览器的今天 | 加载档案后按角色时区确定今天，保留用户主动选择或恢复任务的日期 |
| 缓存已有 45 个日期后生成更早的一天 | 新生成日期被立即淘汰，返回时失败 | 保护本次请求及角色当地当天，限制其余生成缓存 |
| 生成远期年度活动 | 旧年度手工活动被当缓存删除 | 保护手工年度、已清空年度与旧版修改标记，手工日程不参与缓存淘汰 |
| 午夜前准备次日日程失败 | 当前忙碌消息被放行，并触发本会话错误退避 | 次日准备独立退避，当天有效日程继续控制回复 |
| 同一 LLM 请求重复检查 | 原临时提示被替换后，提前告别提示丢失 | 本请求保留自己的告知占用，取消时只释放自己的占用 |
| LLM 前异步切换会话、人设或安排 | 旧请求可能拿到错误角色资料，或漏过新忙碌状态 | 最后重新核对身份及最新缓存；身份变化取消旧请求，新忙碌或积压按最新状态入队 |

## 值得继续增加的功能（本版未实现）

后续状态：下列第 1～3 项已于 v0.3.5 实现。第 4 项仍待评估；新增突发情况方案与持续维护的优先级见 [开发计划表](ROADMAP.md)。以下保留 v0.3.4 检查时的原建议。

1. **情景预演**：选择角色、对话、模拟时间与一句消息，显示基础日程和最终空闲/半忙/忙碌状态、调整原因。默认只读，不发送消息、不改实际日程；调用模型判断应明确触发。
2. **重复纪念日规则**：生日、约定和虚构世界节庆跨年延续。真实农历活动按对应历法计算，自创世界先明确历法映射，避免直接固定成公历日期。
3. **版本快照与撤销**：保存档案、周表、年度活动和当天安排前保留差异及快照，支持恢复误改。现有修订号只表示版本，不等于历史备份。
4. **模型调用统计与预算**：按日程、弹性判断、补回、日记统计调用次数；弹性判断达到上限时保留基础安排，避免频繁对话带来额外消耗。

优先建议先做情景预演和编辑撤销，方便定位实际配置问题并降低误改成本。
