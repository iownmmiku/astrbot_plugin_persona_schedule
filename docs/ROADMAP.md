## INC-01 突发情况

### 默认配置与概率

| 项目 | 默认值 | 行为 |
| --- | --- | --- |
| 启用突发情况 | 关闭 | 同时受插件总开关控制 |
| 触发概率 | 0.2 | 接受有限数值 0～1；WebUI 显示为 0～100% |
| 抽签频率 | 每个人设当地日期一次 | 结果持久化，同一人设的多个会话共享 |
| 每日次数上限 | 1 次 | 刷新、重启、重建日程、恢复编辑快照或重新开启开关不增加机会 |
| 持续时间 | 15～60 分钟 | 限于合适时段，最晚到角色当地午夜结束 |

20% 表示具备可用时段时，当天有 20% 的抽中机会，不是每条消息或每次轮询独立抽签，也不保证每五天发生一次。实际发生还需要生成成功、时段仍适用；概率为 1 也不突破锁定或固定职责限制。已抽签后修改概率从下一个当地日期生效，记录保留当次概率。

### 运行与保护边界

1. 只处理已有当天有效日程的角色，在当天剩余的空闲、半忙时段中寻找机会，不为抽签批量分析新人设。
2. 保存抽签结果。命中后等待触发时刻；尚未发生的事件不进入聊天背景和当天回忆。
3. 使用日程模型，根据人设、世界观、当天安排及近期插曲生成临时事件，不读取私人聊天来创建共享事件。
4. 校验结构、类别、回复状态、时长及重复标题；模型返回后再次核对开关、人设、日期和日程版本。无合适空间、超时、错误或过期结果均跳过，不追溯修改过去。
5. 由基础日程与事件记录计算实际日程。事件结束后恢复当时原本应执行的安排，保留实际发生部分及结束原因。

例如，14:00～16:00 原本休息，14:20 临时需要帮朋友处理事情，14:20～14:50 变为忙碌，之后恢复休息。事件提示词遵循角色身份，不统一套用学生生活；模型对人设和事件语义的理解质量仍需真实模型验证。

睡眠、已忙碌、锁定活动和可识别的固定职责受到保护。事件限于一个可调整时段中的局部插入，不实现无限延期或全天重排。时区变更、夏令时边界、手工修改及过期任务有复核保护。

### 功能协作

| 功能 | 本地实现行为 |
| --- | --- |
| 普通回复 | 突发忙碌时静默暂存；半忙时延迟合并；恢复后按实际日程决定补回时机，并可参考刚才的事情 |
| 命令与范围 | AstrBot 及注册插件命令绕过拦截；空白名单不扩大到所有会话；共享事件不扩大聊天权限 |
| 弹性联系 | 不再适用的旧联系窗口失效，必要时按当前事件重新判断，继续遵守固定职责和有限时长 |
| 提前告知 | 不提前透露尚未发生的随机事件；事件使角色无法联系时保持静默，不向全部会话广播 |
| WebUI | 显示实际时间线、突发标记、状态、原因与历史；可切换查看基础安排、提前结束插曲 |
| 情景预演 | 模拟临时忙碌或半忙，比较原活动与最终活动；不消耗抽签，不修改真实队列或日程；模型权衡单独触发 |
| 编辑与撤销 | 手工修改优先，结束冲突事件的后续影响；编辑快照不回退抽签机会、不删除已发生历史 |
| 日记 | 参考实际发生的片段及白名单素材；未触发、跳过或只读模拟不写成实际经历 |
| 随想画卷 | 开关启用时读取同一份实际日程，在生成前后复核上下文；忙碌或上下文过期时取消旧主动内容 |

事件账本独立于编辑快照。关闭功能会取消后续任务、结束当前影响，但保留已发生事实；重启可延续仍适用的活动，错过的待触发任务和中断的生成任务不会重新执行。独立备份的灾后恢复当天不重新抽签，避免重放已消耗机会。

实现采用短锁记录与提交，模型调用在锁外。消息补回使用稳定内容指纹复核实际安排，联系调整及画卷上下文也包含事件变化。相关实现见 [incidents.py](../incidents.py)、[main.py](../main.py)、[interaction.py](../interaction.py)。

## OPT-01 多页面保存冲突检测

[maintenance.py](../maintenance.py) 为读取结果提供 `edit_token`；保存日程、重复规则、恢复快照、结束突发和应用导入均须提交 `expected_token`。锁内校验失败返回编辑冲突，旧页面不能覆盖新资料。

版本覆盖人设与安排、已发生事件，不因新增聊天素材、队列或统计而无端冲突。页面保留当前日程和规则草稿，可并排比较服务端内容；重新加载前明确确认放弃草稿，不自动合并时间重叠的安排。轮询实际日程也不会替换正在编辑的草稿或偷偷更新其保存基线。

## OPT-02 模型优先级与后台预算

[model_runtime.py](../model_runtime.py) 提供 3 个并发名额，后台最多占 2 个；补回和即时联系判断优先，等待任务随等待时间提升次序。取消等待或执行中的任务会释放名额。

`daily_background_call_limit` 默认 0（不限），按插件配置时区的日期计数，重启保留已用预算。限制针对可选后台调用，不用它关闭基础聊天或阻止用户主动生成。实际重试也计入调用；进入模型前持久化预算，等待结束和提供商选择后再次复核任务是否仍有效。

诊断展示各用途的调用、成功、失败、重试、预算跳过及耗时；只有提供商确实返回用量才显示 token，不估算费用。不保存模型原始回复或含凭据的错误详情作为统计。

## OPT-03 独立备份与恢复预览

[backups.py](../backups.py) 在插件数据目录中维护带格式版本及校验和的独立备份。默认开启，保留 5 份，间隔 60 分钟；界面可手动创建。备份失败提示独立记录，不将已成功替换的主状态当作未保存。

“本地完整备份”包含私有状态，仅保存在本机；“分享角色安排”只导出所选角色的档案、年历、日程、锁定安排和重复规则，不包含聊天原文、会话标识及密钥字段。导入重新校验不可信内容，不能因有校验和而跳过结构和时段检查。

WebUI 恢复需先预览变化，再确认应用选定人设；预览有期限，应用时复核内容版本。只恢复安排，不恢复发送队列、聊天素材或突发抽签记录，恢复前保留编辑快照。

主文件丢失或损坏时可读取有效独立备份，损坏文件保留供排查；灾后恢复会关闭插件控制并暂停旧队列，提示核对，防止自动重放旧消息。没有可用备份时不会静默创建空状态覆盖问题。

## OPT-04 突发诊断与重复抑制

当天记录区分未命中、无合适时段、等待触发、生成中、正在发生、结束、取消及跳过，并显示原因。已消耗机会与实际发生记录分别保留，诊断读取本身不会重新抽签。

生成上下文包含同一角色近期少量插曲的类型和摘要，不跨会话读取私密聊天；近期相同标题被拒绝。类别和上下文帮助减少重复，但不承诺模型每次生成的语义都独一无二，也未加入类型权重设置。

## OPT-05 日记归档缓冲与来源更新

自动归档在角色当地日期结束后等待 `diary_archive_delay_minutes`，默认 5 分钟，可配置为 0～120 分钟。缓冲只作用于自动任务，手动重写仍由用户触发。

归档记录安排指纹与素材采集位置。后续编辑该日安排或新增归属于该日的白名单素材时，页面提示依据已更新，原文保持不变，用户可选择重写。素材自然过期或撤销白名单不会造成反复的“新增素材”提示。午夜后收到的回复归次日，不为拼接对话强行挪到前一天。

## OPT-06 状态存储测量

诊断新增文件字节数、写入次数、失败数、最近/最大/P50/P95 耗时及备份错误。耗时统计使用有界样本，主状态仍采用同步 JSON 序列化与临时文件原子替换，可靠性关键写入保持及时落盘。

已在相同参数下对小、中、大三种合成状态测量前后结果；采用紧凑 JSON 减少格式化及文件体积，没有引入 SQLite 或改变状态架构。环境、完整数据及解释边界见 [存储基准](STORAGE_BENCHMARK.md)。合成事件循环回调延迟不等于真实消息处理或平台送达延迟。

## 验收状态与边界

已完成的本地验证包括：

- 概率校验、每日一次、默认关闭、无候选、固定职责、午夜/时区、重启及配置撤销等突发状态测试。
- 使用受控模型、时钟及消息接口验证忙碌/慢回/恢复补回、过期回复取消、命令绕过、日记实际片段和画卷上下文变化。
- 编辑冲突、草稿保留、恢复预览确认、数据完整性、备份轮换、灾后暂停、后台预算与优先级等回归。
- WebUI 状态测试、JavaScript 语法及页面引用检查；本地演示使用虚构数据和真实插件 handler，不连接机器人账户。
- 三种规模的隔离存储基准，前后使用相同数据结构和采样参数。

真实模型生成是否始终符合角色语气、真实平台端到端消息送达及线上随想画卷联动未据此宣称验证完成。AstrBot SDK 隔离兼容检查、浏览器检查及最终测试结果在版本更新日志中单独记录，不把替身接口或 SDK 返回成功写成真实用户已收到消息。
